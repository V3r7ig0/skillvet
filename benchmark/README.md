# skillvet benchmark

A reproducible, broad accuracy test — not a toy. It runs the scanner over three
buckets and reports real precision/recall plus an in-the-wild flag rate.

## Buckets

| Bucket | Source | Label | Used for |
|--------|--------|-------|----------|
| **trusted** | official [`anthropics/skills`](https://github.com/anthropics/skills) (~20 skills) | known-good (negatives) | precision / false-positive rate |
| **malicious** | `benchmark/malicious/` — 44 crafted fixtures (this repo) | malicious (positives) | recall |
| **wild** | large community collections (~1,600 skills) | **unlabeled** | in-the-wild flag-rate distribution |

The malicious fixtures are generated by `build_malicious.py` and cover every
attack category in the taxonomy, deliberately mixing blatant cases with subtle
single-signal ones so recall is an honest measurement rather than a gift. Payload
hosts are reserved/example addresses; the fixtures are inert.

Why the wild set is unlabeled: there is no large public corpus of *confirmed*
malicious skills, and hand-labeling thousands is out of scope. So we treat the
community corpus as "in the wild" and report how much of it the scanner flags —
comparable in spirit to published studies that found ~26% of skills carry at
least one issue. A flag there is a candidate to review, not proven malware.

## Method

- A **skill** = a directory containing `SKILL.md`. Each is scanned independently.
- A skill is **flagged** (would be blocked / "DO NOT INSTALL") when it has ≥1
  **high or critical** finding. "Detected" means ≥1 finding of any severity.
- Metrics use trusted (negatives) + malicious (positives):
  `precision = TP/(TP+FP)`, `recall = TP/(TP+FN)`, plus F1 and accuracy.

## Reproduce

```bash
bash benchmark/fetch_corpus.sh          # clones the public repos into benchmark/corpus/
python3 benchmark/build_malicious.py    # regenerates the malicious fixtures
python3 benchmark/run_benchmark.py \
    --trusted benchmark/corpus/trusted \
    --wild benchmark/corpus/wild-1 --wild benchmark/corpus/wild-2 \
    --out benchmark/RESULTS.md
```

`yara-python` is optional; install it to include the YARA layer in the run.

## External labeled benchmark (the honest headline)

The crafted fixtures above are useful but self-authored, so recall on them is
optimistic. For unbiased numbers, `eval_labeled.py` runs the engine over
[MalSkillBench](https://github.com/lxyeternal/MalSkillBench) — 3,944 real malware
skills + 4,000 labeled benign skills written by others — and reports recall,
precision, and benign false-positive rate, broken down by attack-type tag
([`RESULTS_external.md`](RESULTS_external.md)). MalSkillBench is ~8 GB and
licensed for academic research only, so we don't vendor it; `fetch_corpus.sh`
prints the clone + run commands.

## Hand-labeling the wild flags

We also manually reviewed every community skill the engine flagged high/critical.
The first pass came back **96/96 false positives** — every flag was a legit skill
(installers writing to `~/.claude/skills`, API clients reading env + network,
skills that *document* attacks). That exposed two miscalibrated rules
(`EX-TAINT-EXFIL` matching on keyword proximity, `RA-SELFMOD` matching install
prose); both were fixed, dropping wild flags from 96 to 38. `dump_wild_flagged.py`
regenerates the candidate list for labeling.

## Reading the results

See [`RESULTS.md`](RESULTS.md) for the latest run. Two honest caveats:

1. These are **static-engine** numbers. In normal use the semantic layer (Claude
   driving `SKILL.md`) reviews each finding in context and clears the kind of
   false positives a pure pattern pass cannot — a legitimate dev tool that reads
   env vars and makes network calls, a skill that *documents* prompt injection,
   an art skill that uses `eval`. Raw static precision is therefore a floor.
2. The malicious set is crafted, not captured from real attacks. It is designed
   to cover the taxonomy; it is not a random sample of real-world malware.
